# 桌面复刻与车机适配记录

## 目标设备

- 比亚迪驱逐舰 05，2023 冠军版
- DiLink 3.0，Android 10，12.8 英寸旋转屏
- 横屏 1920 × 1080；按照实际 Android 显示密度换算 dp，不将截图像素直接当作 dp

## 参考 APK 的已验证结构

分析对象：用户提供的 `F:\h\UI.apk`，包名 `com.xy.launcher`。通过 apktool 2.12.1 解包；业务代码已混淆，以下不代表所有调用链均已分析。

- `res/layout/activity_main.xml`：壁纸 ViewPager2、可隐藏时钟、卡片栏、快捷设置、车控和画中画容器。
- `res/layout/widget_bar.xml`：横向 RecyclerView、模糊背景层和编辑完成按钮。
- `widget_card_*.xml`：导航、音乐、车辆、行程、胎压、应用等卡片。存在删除控件。
- `nav_bar.xml`：应用自身的导航与空调按钮布局，因此不能将截图底栏全部归为原车系统栏。
- 清单声明 `NavBarService`（无障碍）、`MusicNotificationListener`（通知监听）、开机广播、悬浮窗、BYD_CAMERA 和可选 bmmcamera 库。
- 包含 ADB 通信、CoreService 和反射代码。尚未确认系统栏隐藏和车辆数据的完整调用链，不能据此承诺普通安装即可使用。

项目独立实现，不复制原 APK 的业务代码、图标或壁纸。

## 当前实现

- 原创浅色几何背景，图片壁纸和静音循环视频（VideoView 保持视频比例，可能留边，不是系统 Live Wallpaper）。
- 图片采样加载；通过系统文件选择器取得持久化 URI 读取权限。
- Activity 内沉浸模式；滑动可临时唤出系统栏。未禁用或修改系统组件。
- 应用顶部时钟、未连接提示和设置入口；可隐藏顶部栏。
- 底部六个按键，可隐藏、长按绑定到可启动的应用、恢复默认功能。
- 卡片显隐、左右排序和持久化；长按卡片进入管理。
- 导航卡片长按选择已安装的高德、百度或腾讯地图（手机／常见车机包名），保存默认项；默认项卸载后重新选择。
- 音乐卡片封面、歌曲／歌手、播放暂停、下一曲及应用选择；通过用户授予通知使用权访问 Android MediaSession。选择固定应用后不会误控制其他应用，也可自动跟随当前播放会话。
- 活动前台监听会话和元数据变化，后台解除监听；权限撤销后重新进入桌面清空会话。播放器需主动提供媒体会话和对应控制能力。
- 配置变更重建界面；进入后台暂停视频，返回前台恢复。
- 根据手机截图反馈，桌面采用 1200 × 675 设计坐标按屏幕等比换算，不再直接受手机 density 放大；设置对话框继续使用系统 dp/sp。车辆图标改为独立绘制的单色轮廓。

## 尚未实现／明确限制

- 上下栏仅显示于本应用内，不覆盖其他应用；DiLink 是否尊重沉浸模式需实车确认。
- 返回键打开桌面设置，非系统级全局返回；主页键在当前桌面无额外动作。
- 顶栏歌曲已接入媒体会话，网络／蓝牙等连接状态尚未接入。未提供媒体会话的车机播放器无法通用控制，不发送无目标媒体广播作为兜底。
- 导航的回家／停车暂仅打开地图，不设置路线或目的地。
- 车辆、胎压、行程只显示未连接，不发送车辆控制命令。
- 底栏使用独立绘制的单色图标按钮，支持显隐、左右排序和绑定应用，绑定后显示目标应用图标；暂不支持拖拽排序或任意增加按钮。卡片暂不支持任意实例或网格布局。
- 未接管系统 HOME，未开机自启，未实现 ADB 授权和系统栏替换。

## 第一阶段验证清单

1. GitHub Actions 构建安装，手机横屏及车机停车状态截图对照。
2. 顶部栏、底部栏、大时钟开关；即使全部隐藏也可长按壁纸恢复设置。
3. 卡片隐藏、左右移动后重启应用，确认配置保留。
4. 底栏长按绑定应用，重启后启动，卸载目标应用后有错误提示。
5. 图片／视频壁纸选择、重启、后台恢复、更换／恢复默认壁纸、无效文件错误提示。
6. 测试旋转屏及系统栏短暂显示后的布局，确认返回原车界面正常。
7. 长按导航卡片选择高德／百度／腾讯，重启后导航入口仍打开所选应用；未安装地图时提示安装。
8. 开启 CarDesk 通知使用权，音乐应用播放歌曲后返回桌面，检查封面、歌名、暂停／继续、下一曲。切换固定播放器，确认不会控制其他播放器。
9. 撤销通知使用权、停止播放器、播放器不支持下一曲、卸载默认播放器，确认有提示且不崩溃。

本地环境尚缺 Android SDK 和 JDK 17，未完成构建或视觉真机验证。下一步优先细化图标、音乐卡片和状态栏，再研究跨应用系统栏与只读车辆数据。

## 2026-11-10 反馈修订（待设备验证）

### 音乐自动授权回归修订

- 修复缺权限时点击控制只授权却丢弃原操作的问题：保存最后一次明确点击，授权后等待媒体会话最多约3.2秒再发送一次。
- 每次操作刷新所选播放器会话；退后台、重复点击后取消旧请求，避免迟到播放。未找到会话、无播放状态、命令后未观察到状态／歌曲变化时提示，不静默忽略，也不自动重复发送切换按键。
- 2.5秒无反馈提示不等于命令必然失败，播放器可能延迟更新或下一首同名。根因尚未通过车机日志确认，仍待实测。
- 当前分屏入口仍为原生系统多窗口实验，不是桌面内嵌3:7；虚拟屏双应用与触摸转发尚未实现。

### 2026-11-13 车机反馈

- 胎压／能耗截图仅显示本地socket `IOException`，可确定没有收到桥接数据，无法确定是辅助进程未启动、权限、旧进程或 socket 错误。增加桥接启动阶段／异常输出、ADB状态和详细错误；敏感令牌做遮盖，尚未证明桥接修复。
- 分屏截图明确 `Unknown option: --bounds`；去掉Android 10不支持的参数，仅保留windowingMode能力实验。界面移除不可兑现的比例选项，改为左右顺序选择；若第一步失败则不启动第二个应用。最终是否出现真实分屏需停车真机验证，不得把返回码作为分屏成功。

### 导航与音乐真实分屏：第一步能力验证

- 参考APK的 `o/q60.smali` 含 SurfaceView、DisplayManager.createVirtualDisplay 调用；`pip_dual_display.xml` 左侧默认是卡片容器，不能据此认定其左右均为完整应用。
- 新增设置入口：导航与音乐 → 导航与音乐真实分屏。通过本机ADB执行固定结构的 `am start --windowingMode 3/4 --bounds ...`，只使用用户已选地图和播放器的启动组件，检查组件字符，不修改全局force-resizable设置。
- 支持请求音乐30/35/50%、左右交换。系统可能忽略bounds、拒绝不可调整大小的应用或不支持分屏；返回码不能证明两个应用实际分屏成功。此功能仅为系统多窗口试验，不是在CarDesk中嵌入双应用，桌面底栏不覆盖应用。
- 尚未完成构建及实车多窗口测试；停车配置，使用系统Home／最近任务退出。完整桌面嵌入、跨显示触控和生命周期回收仍需进一步研究和开发，尚未实现。

### 2026-11-12 胎压与行程卡片接线

- 胎压卡片接入桥接四轮原始压力：SDK轮位1左前、2右前、3左后、4右后。要求轮胎系统及对应信号状态均为正常，否则显示 `--`；过滤非数值、零、负数及4095无效值。
- 行程卡片接入 `getCurrentJourneyDriveMileage()`、`getLastElecConPHMValue()`、`getLastFuelConPHMValue()`，不是把电池百分比当成能耗。当前分别按km、kWh/100km、L/100km展示；胎压按kPa展示。单位和车型实际缩放仍需与原车显示核对，未实车验证，不做猜测性乘除换算。
- 前台约2秒更新，5秒未收到新数据自动清空，退后台清空。点击任一数据卡片进入诊断，长按仍可管理卡片。
- 辅助进程新增轮胎系统状态。安装新版后旧辅助进程不会自动更新，应断开重启辅助进程（若旧进程仍占用socket，等待30分钟到期或重启车机），否则新字段缺失时胎压显示 `--`。

### 车机实测反馈：音乐授权

### 多任务按钮反馈修订

- 用户车机实测音乐卡片和多任务已可用。多任务ADB过程提示已移除，失败仍提示。
- 地图和音乐选择器统一为浅色圆角紧凑列表。音乐列表按音频Intent、MediaBrowserService、应用类别和常见包名筛选，支持自动跟随；部分未声明音频能力的定制播放器可能无法被识别，自动跟随或现有保存选择仍可用。

- 对照参考 APK 的 `o/a00.smali` 确认其一条路径调用 `AccessibilityService.performGlobalAction(3)`。CarDesk 优先使用同一系统动作；未连接服务或返回 false 时，通过独立本机ADB连接执行固定 `input keyevent 187` 作为新增兼容兜底。
- 检查ADB命令返回码并显示连接错误；命令返回0只表示按键注入命令成功，不能证明厂商最近任务界面已展示。系统动作返回true但无界面变化时不会再次注入，避免重复切换。尚待真车验证。

- 用户反馈车机系统通知使用权页面提示不支持操作。参考APK的混淆字符串解码后确认，其 `NavBarService` 有 `cmd notification allow_listener` 授权路径，并尝试读取 `enabled_notification_listeners`；媒体会话管理使用 `MediaSessionManager.getActiveSessions`。
- CarDesk 的音乐授权按钮现征得用户确认后，经独立的本机ADB连接执行固定命令 `cmd notification allow_listener com.cardesk.home/com.cardesk.home.MusicNotificationListener`，不写入或覆盖其他应用的授权列表。通过系统设置检查结果，而不是仅凭命令成功声称授权成功。
- 通知监听可读取通知内容，界面必须明确告知；仅使用授权后的媒体会话，不自动清理通知。音频应用仍需提供兼容媒体会话。尚未在真实车机验证该命令及系统行为。
- 实测截图中的车速 `SecurityException` 来自普通应用进程直接探测，并非ADB shell桥接的结果；界面现分别显示应用直读和桥接结果，避免误判。

### 车辆 ADB 只读桥接实验

#### 应用内连接（取代下述电脑手工启动流程）

- 默认每次Activity启动自动连接一次保存的地址（初始127.0.0.1:5555），由adbd弹出密钥授权；“启动时自动连接ADB”可关闭。地址和端口默认折叠到高级配置，不扫描端口、不循环弹窗。设备若未开放该端口则不会产生授权弹窗，需要查看连接诊断。

- 设置 → 系统设置 → 无线ADB连接，输入本机地址和传统TCP端口，点击连接并启动。默认127.0.0.1:5555，不代表系统已开放该端口。
- 使用独立生成的2048位RSA密钥，支持传统ADB CNXN/AUTH/OPEN/WRTE/OKAY/CLSE协议。密钥仅保存在应用私有数据，不备份、不复用原APK密钥。首次需在系统确认调试授权；60秒超时可重试。
- 仅允许loopback或本机网卡地址，不能连接其他设备；不支持Android 11+配对码/TLS端口，不启用ADB、不开放端口、不修改权限。
- 连接后只执行固定的app_process启动命令，脚本不拼接用户输入；ADB shell保留至进程退出或用户断开。断开关闭传输，不承诺终止已启动辅助进程，辅助进程仍有30分钟上限。
- 连接属于当前Activity生命周期，退出销毁时断开，不后台自动重连。前台通过本机socket读取桥接数据；ADB认证与桥接成功分别报告。
- 待实测：已授权密钥直连、新密钥授权/拒绝/超时、错误端口、TLS端口、断开取消、反复连接、辅助进程启动失败、30分钟到期。当前未完成Android构建和端到端协议测试。

- `VehicleBridgeMain` 是独立编写的 `app_process` 入口，**必须从已授权电脑的 adb shell 手工启动**；当前没有内置 ADB 客户端、自动连接或自动拉起。设置中的“车辆只读桥接”可复制启动命令。
- 仅接受 shell UID 执行，本机抽象域 socket 校验对端 UID 和随机令牌；主应用也检查服务端 shell UID。进程 30 分钟退出，仅支持读取，不暴露通用命令或空调控制。命令中的令牌视为敏感信息，不要公开分享，复制后清除剪贴板。
- 读取轮胎原始压力及信号、风量、空调开关／循环、速度、最近能耗及行程原始值。数据放在设置诊断中；车型参数、单位、无效值尚未验证，不显示为正式胎压／能耗／车速，更没有车辆命令写入。
- ADB 端口、shell 身份、系统 Context 与反射是否在目标 DiLink 可用都尚未验证。服务不具备认证防重放或系统级安全边界，用户应只在可信、停车环境测试；请勿将 ADB 暴露给不可信网络。
- 验证：手机上应显示未连接；车上通过电脑复制并执行启动命令，回到设置查看诊断；若失败收集电脑控制台错误和诊断截图。进程到期、升级重启或车机重启后需重新启动。

- 底栏分为左侧返回、Home、多任务、所有应用，中间空调占位区，右侧可配置快捷功能。空调显示 `--°`，点击只提示未连接，不发送车控命令。
- 返回及多任务通过用户自行启用的无障碍服务执行系统全局操作；不读取窗口内容。Home 在当前桌面内提示已在桌面，未将应用设为系统默认桌面。底栏不跨应用显示。
- 所有应用改为浅色六列紧凑网格。多任务使用系统原生最近任务界面，外观由系统决定，无法通过普通应用统一改造成自定义浅色界面。

- 大时钟未保存配置时默认显示，保留用户已有开关。左上角默认显示车速，支持开关和定位授权入口。
- APK 检出 `android.hardware.bydauto.speed.BYDAutoSpeedDevice.getCurrentSpeed(): double` 及 `AbsBYDAutoSpeedListener`。APK 中该类为抛出 Stub! 的 SDK 占位类，并非可复用实现。新代码只通过反射探测系统实现，不复制 SDK 或绕过权限。
- 后台线程进行一次只读接口调用，系统设置中查看结果。尚未连接真车，无法确认单位、实时性及权限，因此没有自动使用接口数值作为速度，也未实现 ADB 桥接。
- GPS 作为当前可用来源：只在前台订阅GPS，使用定位自带 speed（m/s 转 km/h）；5秒未更新、无速度或异常值时不展示旧速度，不用距离差推算。不申请后台定位权限。

- 设置重做为亮色三分区面板：左侧分类、中间双列设置卡片、右侧目标设备和实际设备／版本信息。分类和内容支持滚动，开关即时保存，不再使用黑色按钮堆叠。
- 统一应用浅色主题，卡片、按键管理及应用选择等二级对话框也采用浅色；应用列表文字同步改为深色。

- 卡片收紧为设计坐标宽度：导航 215、音乐 235、其他 190，不再每张占屏幕宽度 22.3%。
- 通知监听服务连接及通知更新时刷新前台会话；同一会话保留回调，减少反复注册。
- 不再仅因播放器未声明 actions 标记而拦截播放和下一曲请求；仍只控制选定会话，不发送全局广播。
- 设置增加音乐连接诊断，报告通知使用权、所选包名、系统可见会话、播放状态和操作标记。无法使用时需用户提供诊断截图及播放器版本，尚未确认故障根因。
- 新参考图中的温度、风量、锁车等未接通车机接口，不显示伪造温度或可点击的假车控。
