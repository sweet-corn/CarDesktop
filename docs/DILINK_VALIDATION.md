# DiLink 3.0 实测清单

目标：驱逐舰 05 2023 冠军版，DiLink 3.0 / Android 10，1920 × 1080 横屏。请停车、保留原厂桌面，在可信网络测试。

## 参考及实现

- `qgzm.apk` 的胎压和行程管理器验证了 `getTyrePressureValue`（显示 kPa）、`getLastElecConPHMValue` 和 `getLastFuelConPHMValue` 的调用及有效值范围。电耗可为负值（能量回收）。不沿用参考应用跨异常使用缓存的行为。
- `ZhiUI.apk` 的 SDK 声明验证了轮位 1 左前、2 右前、3 左后、4 右后；空调 `1` 开、`0` 关，温标 `1` 摄氏、`0` 华氏。温度与风量不作猜测换算。
- 不覆盖厂商 SDK 的权限检查；无线调试不赋予应用签名权限。新的桥接由本机 ADB 启动 shell 辅助进程并通过该会话的输出流发送快照，不再依赖 app 与 shell 跨 UID 访问抽象 socket。每个字段保留独立错误。
- 两个参考 APK 都有虚拟显示路径。CarDesk 只把右侧导航放进独立虚拟显示；左侧复用现有 MediaSession 控件，不嵌入另一个播放器 Activity。虚拟屏触控只尝试指定显示 ID 的单指点击／滑动，不向主屏回退发送触摸；返回桌面、旋转、进入后台会释放虚拟屏。

## 测试顺序

1. 构建安装，打开“设置 → 系统设置 → 无线ADB连接”，确认系统授权弹窗。查看“车辆只读桥接”：`BRIDGE_START`、`BRIDGE_CONTEXT_READY`、第一份快照分别对应启动、系统 Context、开始采样。若未到第一份快照，记录启动输出；若字段带 `_error`，保留字段名及异常内容。
2. 对照原车界面检查四轮位置、压力、当前里程、最近油耗和电耗。确认无信号、不支持字段和主动断开显示 `--`，重连恢复。预期不会把桥接已启动当成所有车辆接口已可用。
3. 检查底栏空调的开关、主副驾温度和风量。停车时从面板执行一次开关或风量请求，确认辅助进程的返回结果和原车实际变化；超时或结果未知时先检查原车状态，不立即重试。暂不提供温度、风向或循环写入。
4. 设置默认地图，横屏点击导航卡片的 `3:7`。检查右侧地图是否真的绘制、点击和滑动是否生效，左侧音乐能否继续播放／暂停／切歌。若失败，记录地图包名、版本和分屏页面提示；验证“全屏打开地图”可用，以及关闭后能再次进入。
5. 如需收集日志，在停车状态用已授权设备执行 `adb logcat -d -s CarDeskBridge ActivityTaskManager AndroidRuntime`。不分享任何 ADB 密钥、设备识别信息或无关私有日志。
